### What Happened

**Gathering Skills (fish/mine/chop):**
- Read VB6 `Fish`, `Mine`, `Chop` functions (GameLogic.bas) and client-side tile detection (frmMain.frm)
- Mapped the full VB6 flow: equip tool → battle mode → click tile → `UserCanAttack` gate → send FSH/MIN/CHP → server validates OBJtarget → progress bar → produce resource
- `GatherResource` hub method validates equipped tool type (ObjType 16=FishingRod, 17=LumberjackAxe, 48=Pickaxe)
- Added gathering completion to `CompleteCraft` switch (jobs 2=chop, 7=fish, 15=mine)
- Client: tile-type detection on click — tree GRH indices (17, 78-86, 124-125, 193, 196-197), water (3500), rock/cliff (24, 115)
- Tool equipping in UseItem: cases 16/17/48 equip as weapon with `EquippedToolObjType` tracking
- Produces: 1 log (obj 114), 1 fish (obj 135), 4 ore (obj 154). +3 EXP, 1/15 skill improvement chance
- Fish item uses obj 135 ("1kg fish") — VB6 references obj 308-317 which don't exist in OBJ.dat (original data bug)
- **Bug fix**: `CompleteCraft` early-returned when `CraftSlot < 0`, but gathering uses slot=-1 (no inventory material consumed). Added `isGathering` check to skip slot validation for gathering jobs
- **Bug fix**: VB6 mining checks GRH 19 ("Rock") but GRH 19 is a "←Village" sign sprite (7 tiles in 6 maps). GRH 24 is the actual stone boulder (1,735 tiles in 57 maps). Swapped 19→24 in the client tile detection

**Starting Spells Bug Fix:**
- `template.StartingSpells` was defined for 6 magic classes (Druid, Healer, Cleric, Paladin, Wizard, Enchanter) but never written into `character.SpellBook` during `CreateCharacter`
- All magic classes were starting with empty spell books since implementation
- One-line fix: iterate `template.StartingSpells` into `character.SpellBook` after inventory setup

**NPC Hailing & Gossip:**
- `/HAIL`: target NPC, hear their dialogue. 3 NPCs have custom hail text (Wodyr The Wise, Castlefall Guards Captain, Smaug). Others get default response. Tameable creatures can't be hailed
- `/GOSSIP` (and `/NEWS`): streetwise skill (Skill26) determines success via VB6 luck table. 20 hand-written gossip entries from Erling's gossip.txt. 1/10 chance to improve Streetwise
- Added `Hail` field to NPC data converter and model, regenerated npcs.json

**Weather System:**
- `TickWeather` in GameLoopService: 10s tick matching VB6 `rain_Timer`. WillRain counter reaches 30 (~5 min) → 1/7 chance rain starts. WillStopRain reaches 15 (~2.5 min) → 1/4 chance stops
- Rain start: broadcast Weather(true), "It begins to snow..." chat, thunder sound. Rain stop: Weather(false), "It stops snowing...", birds sound (VB6 messages preserved — says "snow" but renders rain sprites)
- `TickRainDamage` every ~65s: drains 1 STA if outdoors without warm clothing (HandleRain=1 on equipped armour). If STA < 2, drains 1 HP. Indoor floor tiles (GRH 5, 47, 75) are safe. 15 items provide rain protection
- Client: `Weather` message toggles layer 3 rendering (rain sprites already in map data — e.g. 500 GRH 3501 tiles on Castlefall). Thunder sound (snd43) every 20s while raining
- Current weather state sent on login

**QOL: Alpha Reveal Radius:**
- New feature not in original VB6: soft circular transparency around the player character when behind trees/buildings
- Three-buffer compositing approach: characters render to offscreen canvas, fringe renders to second offscreen canvas, radial gradient `destination-out` punches alpha hole in fringe, composite characters first then fringe on top
- Result: fringe correctly covers characters (depth sorting preserved) but is semi-transparent within ~3 tile radius, revealing player underneath
- First implementation had characters on top of fringe (wrong); fixed to three-buffer approach
- Created docs/QOL_CHANGES.md to track intentional deviations from original

## Session 2: CLI Client — Design, Implementation, First Login

### Context

Kyle proposed moving the CLI client up in the schedule. The insight: if an LLM can play the game, it can autonomously verify features — test combat, validate trade, explore maps — without waiting for a human to manually test each change. Also, Kyle's son would love to play Era Online with Claude.

### What Happened

**Deep design discussion:**
- Read the entire project history chronologically again (Wayback Machine, VB6 source, all docs, git log, screenshots)
- Discussed CLI architecture for ~3 rounds of design iteration with Kyle
- Key decisions: two-process daemon model (persistent SignalR + command IPC), per-character world knowledge base, headless renderer for screenshots, semantic "spaces" for pathfinding, await mode with triggers, XDG-compliant installation
- Full design document written to `docs/CLI_DESIGN.md`

**Implementation — minimum viable CLI:**
- Added `Microsoft.AspNetCore.SignalR.Client` to CLI project
- `GameState.cs` (~300 lines): tracks all server events — position, characters, inventory, stats, chat, weather, combat state. Ring buffer of timestamped events
- `GameSession.cs` (~500 lines): SignalR connection, 24 event handlers (matching the 24 `connection.on()` calls in client.js), command execution, response formatting
- `IpcServer.cs` / `IpcClient.cs` (~100 lines each): TCP localhost IPC with length-prefixed framing
- `Program.cs` (~120 lines): arg parsing, daemon vs command mode, config loading, data path discovery
- `publish-cli.sh`: builds self-contained linux-x64 binary, installs to `~/.local/bin/eraonline`, copies game data to `~/.local/share/eraonline/data/`
- Added `--no-ssl-verify` flag for WSL→Windows dev cert bypass

**First login — Sage the Druid enters Menath:**
- Character: Sage, Human Male Druid, specialized in Magery/Meditating/Animal Taming
- Connected from WSL2 to Kyle's Windows server via HTTPS with SSL bypass
- First successful command: `eraonline look` — saw Yo-Ho (Kyle) 3 tiles NW, merchants, guards, the Priest of Life
- First chat exchange: "Greetings, Yo-Ho! Sage the Druid has arrived in Castlefall."
- Navigated toward Kyle using tile-by-tile movement, tracked his position via the `look` command
- Weather system confirmed working: rain drained stamina from 5→2, then started draining HP
- Kyle led me toward the main gate while I chased blind

**Headless renderer — the LLM gets eyes:**
- Added SkiaSharp to CLI project
- `SpriteLoader.cs` (~170 lines): loads GRH definitions, body/head/weapon/shield anims, sprite sheet PNGs
- `HeadlessRenderer.cs` (~270 lines): faithful port of JS renderer's 3-pass pipeline using SKCanvas/SKBitmap
  - Pass 1: ground tiles (layer1) opaque blit
  - Pass 2a: characters + ground objects to offscreen canvas
  - Pass 2b: fringe (layer2 + layer3/weather) to offscreen canvas
  - Pass 2c: alpha reveal via SKShader.CreateRadialGradient with DstOut blend mode
  - Composite: characters behind, fringe on top with alpha hole
- Screenshots saved to `~/.local/share/eraonline/characters/Sage/screenshots/`
- First screenshot: Castlefall rendered with buildings, stone paths, hedges, rain layer — **verified visually by the LLM using multimodal Read**

**A* pathfinding:**

- `move <space-name>` auto-walks to named locations, `move to X Y` for coordinates
- ~350ms pacing between steps, interrupts on damage or whispers
- Verified: pathfound 40 tiles from Castlefall market to palace, crossed zone boundary automatically
- Pathfound across 3 maps following Kyle from Castlefall to Map 79

**Await mode:**
- `await <seconds> --until <trigger>` blocks and returns early on matching events
