# 2026-04-02

## Session 1: Phase 2 Debugging + Visual Verification

### What Happened
- Debugged static file serving issue where sprite PNGs returned 404 in browser
- Root cause: custom PhysicalFileProvider path resolution worked differently across environments (WSL2 vs Windows)
- Fix: moved all game data (JSON + 810 PNGs) into src/Client.Web/wwwroot/data/ and used standard WebRootPath serving
- Committed data files to git so the project works immediately after clone
- Server now uses WebApplicationOptions.WebRootPath pointing to Client.Web/wwwroot - single UseStaticFiles() serves everything
- Added HTTPS support and binding to all IPs (0.0.0.0:5000/5001) for cross-environment access
- Added arrow key panning to explore the map

### Milestone: Castlefall Renders in the Browser
Kyle confirmed visual verification - Castlefall (Map 81) renders faithfully:
- Ground tiles: grass, stone paths, dirt - correct textures and placement
- Fringe layer: buildings with roofs, stone walls, wooden doors, trees - transparency working
- Objects: barrels, torches, lanterns, flower hedges visible
- The Theatre: wooden stage, stone columns, lampposts - matches original screenshots
- NPC characters: visible at spawn positions with correct body sprites
- Arrow key panning allows exploring the full 100x100 tile map

### Design Decisions
- Game data tracked in git rather than gitignored - eliminates setup steps after clone
- Single WebRootPath approach instead of multiple PhysicalFileProviders - simpler, more portable
- Sprite PNGs in wwwroot/data/grh/ alongside JSON in wwwroot/data/ - one data directory for everything the client needs
