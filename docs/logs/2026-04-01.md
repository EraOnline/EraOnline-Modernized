# 2026-04-01

## Session 1: Deep Dive + eo-data-converter

### What Happened
- Full immersive exploration of the Era Online codebase, original website, screenshots, manual, and changelogs
- Fetched eraonline.net from Wayback Machine (Nov 1999 through 2009 captures) - read homepage news posts from the era
- Investigated all binary data file formats by reading VB6 loader code and parsing raw hex
- Key discovery: Head.dat, Body.dat, shanim.dat, wpanim.dat are all INI format despite .dat extensions - only Grh.dat and map files are truly binary
- Map binary format reverse-engineered: .map = 7 bytes/tile, .inf = 12 bytes/tile (files are 160KB but only 120KB used, trailing 40KB is empty space)
- Built eo-data-converter tool (C#, 15 source files) that converts all original game data to JSON
- Output: 222 JSON files (305 objects, 278 NPCs, 16 spells, 211 maps, 4,050 sprites, heads, bodies, anims, config, gossip, quests)
- Cross-validation passes for NPC spawn templates, object GRH indices, animation frame references

### Design Decisions
- Game data loads from pre-converted JSON rather than parsing original VB6 formats at runtime
- Models use [JsonPropertyName] attributes to match eo-data-converter output directly
- Map tile arrays are flat int[] indexed by (y-1)*100+(x-1) for performance
- VB6 naming translated to clean C#: MinHP->CurrentHp pattern documented but deferred (the data model uses the JSON names for now, runtime models with cleaner names will come in Phase 4)
- vb6-ast annotate only works on subs/functions, not types/constants - annotations will be most valuable during Phase 3+ when porting game logic

## Session 3: Phase 2 - Rendering Engine

### What Happened
- Added BMP-to-PNG sprite sheet conversion to eo-data-converter using SkiaSharp
- 810 BMP sprite sheets converted to PNG with alpha transparency (black->transparent), 7.2MB total
- PNGs are gitignored (regenerated by running the converter)
- Built JavaScript renderer module (renderer.js) - faithful port of VB6 RenderScreen:
  - GRH system: loads sprite atlas definitions from grh.json, resolves animation frames
  - Sprite sheet loader: on-demand PNG loading, preloads sheets for visible map
  - 3-pass map renderer: ground tiles (opaque), fringe layer (transparent/centered), characters
  - Character compositing: head (with HeadOffset) + body + shield + weapon, directional sprites
  - Viewport: 20x11 tiles centered on camera position
- Configured Server to serve Client.Web wwwroot + eo-data-converter/data at /data
- All endpoints verified: index.html, renderer.js, grh.json, sprite PNGs, map JSON, heads/bodies/anims
