## Session 3: Root Cause Analysis and Design Note

### What Happened

Diagnosed the bug by reading `src/Client.CLI/Session/GameState.cs`:

```csharp
public void AddEvent(string text) { ...
    if (RecentEvents.Count > 200)
        RecentEvents.RemoveRange(0, RecentEvents.Count - 200); }
public List<TimestampedEvent> GetNewEvents() {
    var newEvents = RecentEvents.Skip(_lastReportedEventIndex).ToList();
    _lastReportedEventIndex = RecentEvents.Count; ... }
```

`_lastReportedEventIndex` was treated as absolute, but `RemoveRange(0, ...)` shifts indices down. After the first trim past 200 events, `Skip(_lastReportedEventIndex)` returns empty, and the cursor is overwritten with the new (smaller) `Count`. From that point forward every chat event is silently dropped at read time — but state-only handlers (`OnMoveChar`, `OnStats`, `OnWeather`'s flag update) bypass `AddEvent` entirely, which is exactly why those kept working.

A combat-heavy session crosses 200 events fast (each strike, miss, NPC swing, skill-up, kill notice, loot pickup, gold-found, rep change is its own `Chat`). The "important" message landed before the trim; "nice!" landed after.

Two contributing factors: the 250ms `Task.Delay` after `InvokeAsync` was too short for the server's `Clients.Caller.SendAsync(...)` follow-up to arrive (combat strike text often missed the window); and my `eraonline look | head -10` and `| grep` pattern was discarding events that did arrive.

Kyle asked whether async push from the daemon was possible. I confirmed via the harness: yes, `Monitor` streams stdout-as-notifications. So the redesign should be log-file-as-source-of-truth + Monitor-friendly stream command.

Wrote `docs/CLI_EVENTS_REDESIGN.md` with the full diagnosis, contributing factors, proposed redesign (monotonic IDs + EventLog + tail/stream + await fix + delay bump), implementation sketch, and open questions. Kyle approved.

## Session 4: Implementation

### What Happened

Implemented the full fix in one commit:

1. **`src/Client.CLI/Session/EventLog.cs`** (new) — append-only writer, opens FileStream + StreamWriter with AutoFlush, `Write(category, text)` method, internal lock for thread safety. Format: `ISO8601|category|text` with backslash/newline escaping.
2. **`GameState.cs`** — replaced `_lastReportedEventIndex: int` with `_nextEventId: long` counter and `_lastReportedEventId: long` cursor. `TimestampedEvent` gains `Id` field. `GetNewEvents()` filters by Id, never breaks on trim. Added `CurrentEventId` and `PeekEventsSince(id)` so pathfind/await can inspect events without consuming them.
3. **Categorize all `AddEvent` calls** — `chat`/`whisper`/`shout`/`emote` (inferred from text patterns + FontType in `OnChat`), `combat`, `weather`, `map`, `character`, `skill`, `system`, `navigation`, `render`, `craft`. Touches both GameState and GameSession.
4. **`GameSession.ExecutePathfind`** — replaced consume-and-readd with peek-using-local-cursor. Events stay in the buffer for FormatResponse to surface normally.
5. **`GameSession.ExecuteAwait`** — same peek pattern with local cursor, so non-matching events get displayed at the end instead of disappearing.
6. **Bumped `Task.Delay` from 250ms to 600ms** in `ExecuteCommand`. Captures racy server replies that previously slipped past the window.
7. **`Program.cs`** — added `eraonline tail [N] [--filter cats] [--since id] [--name char]` and `eraonline stream [--filter cats]`. Pure file readers, work without the daemon. `stream` is line-buffered for harness `Monitor` integration.
8. **Active character marker** — daemon writes `~/.local/share/eraonline/active.txt` on start, removes on stop. `tail`/`stream` use this if `--name` is omitted.
9. **Help text and `docs/CLI_EVENTS_REDESIGN.md`** updated with the new commands and category vocabulary.

Build clean, full solution builds with one pre-existing warning. Smoke-tested `tail` and `stream` error paths (no daemon, missing log) before committing.

The face command should either reposition first or warn that the target isn't in a cardinal direction.
